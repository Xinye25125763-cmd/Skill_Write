# Skill Forge：把技能想法整理成可验证的技能成果

Skill Forge是一套面向个人使用的本地技能工作台，帮助你整理skill需求、管理技能文件和版本，并通过真实模型执行与程序测试观察技能是否有用。当前交付为v1.1工作台；“创建skill的前置skill”是推荐的接入方式，独立前置指令包尚未安装。

## 它可以帮你完成什么

| 你想做的事 | Skill Forge提供的能力 | 你能得到什么 |
|---|---|---|
| 把零散需求整理清楚 | 导入用途、触发场景、输入输出、工具和验收标准；区分明确、推断与待确认 | 可追溯的需求记录与修订历史 |
| 编写或完善一个skill | 编辑SKILL.md及配套参考文件、脚本，检查结构和文件引用 | 一套结构清楚的技能文件 |
| 保留每一次修改 | 冻结版本、记录内容指纹和关联需求 | 可以回看和复测的版本快照 |
| 看技能能否完成任务 | 接入兼容模型，让它按技能说明读写文件、运行支持的脚本 | 最终答复、文件产物、执行轨迹和用量 |
| 判断技能是否带来提升 | 同一测试集分别运行候选技能和无技能基线 | 两组程序断言成绩、失败原因和逐例证据 |
| 保存自己的成果 | 停服导出数据备份，恢复到空目录 | 可迁移的项目、版本与评测记录 |

需求目前由你或外部AI整理后导入；技能正文由你或技能创建工具编写。工作台负责保存、校验、运行与评测，保留完整编辑和脚本使用能力。

## 一个具体例子

你想制作“个人周报整理skill”：

1. 明确输入素材、固定结构，以及“不虚构进度”的要求。
2. 将需求导入工作台，写入SKILL.md和周报模板。
3. 保存v1版本，提供一组真实素材进行试跑。
4. 检查是否生成周报、是否包含必需章节，以及是否忠实于素材。
5. 使用相同用例比较“有技能”和“无技能”的表现，再据此修改v2。

工作台能自动检查文件是否存在、文本是否包含指定内容和任务退出原因；事实忠实性、整体表达质量仍需人工判断。

## 作为创建skill的前置环节

推荐流程：

**整理目标与验收要求 → skill-creator或其他创建流程生成技能 → Skill Forge保存版本并评测 → 在实际宿主中验收。**

这种方式适合把经常重复的工作沉淀成skill，也适合完善已有技能，减少需求遗漏并为修改保留证据。前置环节应复用已明确的要求，保留全部功能，不要求每次都重新填写一套冗长问卷。

## 使用前需要知道

- 不接模型也能管理项目、需求、草稿和版本；试跑与评测需要模型端点。服务商收费按实际调用计算。
- 数据保存在本机；使用远程模型时，提示词、技能正文和进入对话的工具输出会发送到该端点。
- 脚本运行在普通本地进程中，目录沙箱提供路径约束；应使用自己编写或检查过的技能资源。
- 当前尚未实现自动生成闭环、原生宿主触发优化、盲评和自动安装。现有测试成绩也不能代替在Codex等实际宿主中的触发验收。

适合需要认真维护个人技能、希望看见执行证据和评测结果的人。更详细的实际流程见[内部完整流程与实现详解](Skill-Forge-v1.1-内部完整流程与实现详解.md)。
