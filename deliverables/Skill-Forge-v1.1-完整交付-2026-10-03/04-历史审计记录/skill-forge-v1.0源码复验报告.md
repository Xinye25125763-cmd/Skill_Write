## 4. 需要继续修复的问题

### R01 — P1：运行中的模型调用在删除后仍执行工具

位置：`app/services/projects.py:249–286`；`app/executors/api_executor.py` 模型返回后的工具调用循环；`app/workers/handlers/agent_run.py:169–178`。

复现流程：Worker 开始 agent_run → 本地假模型在 complete 内等待 → API 删除项目，返回 204 且目录消失 → 假模型返回 write_file 工具调用。

实际结果：工具仍执行并写入 late.md，重新创建被删除的项目目录；Worker 随后出现 PendingRollbackError。数据库 cancelled 状态不代表模型请求与执行器已停止；当前只在下一轮开始查取消，不能阻止本轮返回的工具操作。

建议：删除期间先进入 deleting、停止新调度，并等待执行端确认停止后再删除；或明确拒绝删除仍运行的项目。模型返回后及每个工具前重新检查取消与所有权。运行结果提交也需防止引用已经删除的项目；异常路径 rollback 后再收尾。

### R02 — P1：删除流程宣称单事务，实际取消已经提前提交

位置：`app/services/projects.py:254–258`；`app/services/queue.py` 的 request_cancel、mark_cancelled、append_event。

这些队列函数内部执行 commit，因此调用后整个删除过程不是同一事务。

补充复现调用真实 ProjectService.delete，在最终 session.delete(Project) 前注入异常再 rollback。实际项目保留，但关联任务已永久 cancelled，无法整体恢复。

现有 tests/test_project_delete.py:159–177 将完整 delete 方法替换为只删除需求再抛异常的 broken_delete，没有走真实取消与提交路径，因此不能证明真实删除操作整体回滚。

建议：内部服务支持不自动提交，由业务边界控制数据库事务；若取消与删除本来是多阶段流程，显式记录阶段并提供补偿。失败注入测试应保留真实 delete，仅在关键数据库或文件操作注入故障。

### R03 — P2：磁盘删除失败后数据库项目已丢失

位置：`app/services/projects.py:280–286`。

项目删除先 commit，随后 rmtree。补充探针让 rmtree 抛 PermissionError，实际数据库项目已不存在、磁盘目录仍保留，rollback 无法恢复已提交的数据库数据。API 会返回失败，但用户无法从列表恢复该项目。

建议：采用可恢复的删除状态与清理任务，或先重命名到隔离目录并保存恢复信息；明确数据库与文件系统不存在共同事务，不能仅写“失败整体回滚”。

### R04 — P1：预算已耗尽时仍执行工具

位置：`app/executors/api_executor.py:145–155`。

消耗后检查仅覆盖无工具且 finish_reason != stop 的情况。独立探针设置预算 100，假模型返回输入输出合计 115 token 并请求 write_file：文件实际写出，下一轮才退出 budget_exceeded，且返回 sandbox_files 为空。预算耗尽后仍执行新增工具操作，结果记录也遗漏已产生的文件。

正常 stop 超预算仍 completed 是新版明确写入测试的语义选择，不单独判定为回归缺陷。但没有单独的预算违规标志与超额数量，需要同步产品定义和报告，不能将其描述为严格总预算上限。

建议将任务结果和预算合规分开记录，或保持严格预算状态语义。调用前估算输入，限制本次输出，调用后记录超额；已经发生的费用不能撤回。不要在预算已耗尽后继续发起新工具或模型调用。

### R05 — P2：存在第二个 Worker 时，慢调用可被误判中断

位置：`app/executors/api_executor.py:116,143`；`app/workers/handlers/agent_run.py:136–137`；模型适配器默认 timeout 120 秒。

心跳在步骤完成后才 touch，默认租约为 60 秒。独立探针使用假时钟模拟模型调用 61 秒，并在另一个数据库 Session 执行恢复扫描：仍在执行的任务被置 interrupted；随后执行器返回 completed，但 queue.complete 因终态保护不提交结果，job result 为 None。

触发需要另一个 Worker 或独立恢复扫描者；单 Worker 同步执行时不会同时扫描自身，因此不宣称普通单 Worker 必然遇到。建议禁止或协调重复 Worker，或者采用独立心跳并按 Worker 所有权处理租约失效。

- launcher.py 仍只打印不带 token 的 base_url；指南说可以从终端复制带 token 的 URL，但当前源码未打印该 URL。自动打开失败时应提供可用的手动入口。
- backup 实现仍只有 manifest 元信息与 SQLite quick_check，未发现逐文件哈希校验；Mac 指南中的“清单哈希、防篡改”声明仍不成立。
- 指南中的端口、数据外发、密钥落盘和过强恢复保证，继续按上一份文档复核报告修订。
