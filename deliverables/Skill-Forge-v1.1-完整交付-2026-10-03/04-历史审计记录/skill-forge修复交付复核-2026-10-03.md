## 3. 文档中必须修正的内容

### D01 — 用户使用指南的数据外发声明不准确

位置：用户使用指南.md:5。

“全程数据都在本地，不上传任何内容”与远程模型执行不一致。远程执行会发送提示词、技能正文及工具返回内容；脚本也可能自行联网。

建议改为：“项目及运行记录存储在本地；使用远程模型时，会向配置的提供商发送执行所需内容。使用本地模型时，按其实际部署方式说明数据流向。”

### D02 — 密钥不落盘的说法与持久配置建议冲突

位置：用户使用指南.md:49–50；Mac迁移与使用指南.md:104–115。

指南建议将密钥写入 start.ps1 或 ~/.zshrc，同时称其只存在环境变量、不落盘。脚本和 shell 配置文件本身就是磁盘文件。

建议区分应用不主动保存密钥与用户主动保存环境配置。首选系统凭据存储；如选择脚本方式，明确密钥会以明文保存在配置文件。密钥不进日志与产物还需验证脚本环境继承、异常输出和脱敏机制，不能仅以应用不写数据库来保证。

### D03 — Mac 指南的端口与其他文档不同

位置：Mac迁移与使用指南.md:96,116；内部技术说明.md:32,318。

Mac 指南使用 8317，技术文档与现存配置使用 8710。除非新版配置明确变更，否则应统一；需要以新版 config.yaml 和 ServerConfig 为准。

### D04 — 备份防篡改声明缺乏对应实现说明

位置：Mac迁移与使用指南.md:141–142；内部技术说明.md:253–266。

Mac 指南声称备份有清单哈希校验、防篡改，但内部文档只描述 manifest 元信息、路径检查和 SQLite quick_check，没有逐文件哈希生成及恢复比对。现存旧实现也不含这项验证。

需提供新版实现和篡改包测试，或收窄为“数据库结构完整性与归档路径校验”。内容哈希只能在清单可信时检测更改；如果攻击者能同时重写文件及清单，普通哈希不提供真实性保证。

### D05 — “不会发生了”与跨平台保证过强

位置：Mac迁移与使用指南.md:187–188、末尾；审计修复报告末尾。

周期清扫不能保证任何 running 都会自动消失；Worker 未启动、失去响应、长调用和心跳方式都影响恢复。准确描述应为“在 Worker 正常运行且清扫与租约配置有效时，过期任务按策略标记中断”，并写出排障步骤。

采用 pathlib 等跨平台 API 不等于已经完成 macOS 验收。应区分“按跨平台方式实现”与“在某版本 macOS、Python、Node 上实测通过”。

## 4. 修复策略中需要重点复验的两项

### R01 — F10 改变了预算语义，没有完整消除原问题

修复报告声明：超预算但 finish_reason=stop 时仍算 completed。前期 F10 指出的是超过总 token 预算仍完成，该策略保留了该行为，只对特定退出原因改变分类。

如果产品选择允许任务完成但超支，应将“任务完成情况”和“预算合规情况”分开记录，例如 completed + budget_exceeded=true、实际超额数量；UI 与报告显式展示，不得称为严格总预算上限。若保留硬上限定义，则正常 stop 超预算也需要标明预算违规。

还要确认工具调用响应超预算后，不再调度额外工具或下一轮。调用前输入估算与输出上限仍不能保证已发生费用可撤回。

Mac 指南建议 length 时仅调大总 token 预算重试，但内部文档仍写单次输出 max_tokens=min(4096, remaining)。若截断由 4096 单次上限引起，调大总预算不会改善，需要单独的每次输出上限配置或续写策略。

### R02 — F04 删除时先置 cancelled 再删除目录存在并发风险

修复报告描述在单事务内直接把在途任务标为 cancelled，再删除记录并 rmtree。数据库状态变为 cancelled 不代表正在运行的模型请求或脚本已停止。

必须复验：运行长模型调用或脚本时删除项目，Worker 是否在返回后继续执行工具、重建目录、写入已经删除的项目，或触发外键错误。建议先进入 deleting 状态、请求取消并等待 Worker 确认停止，或拒绝删除仍在执行的项目；最终清理要有恢复记录。

活跃任务心跳也需复验：文档仍称在模型/工具步骤结束时 touch，单次模型超时为 120 秒而默认租约 60 秒。需证明慢调用期间不会被另一 Worker 错判过期；周期清扫与独立心跳、Worker 所有权和租约配置应协调。

上述为修复方案风险，不是已在新版源码复现的缺陷。
