README 明确定位为第一阶段 S1–S7，本报告将现有实现缺陷与完整产品待交付功能分开。后者不是判定第一阶段失败的依据，但不能从最终范围删除。

## 3. 已确认的实现缺陷

### F01 — P1：默认相对数据目录导致脚本无法执行

位置：`app/tools/registry.py:135–151`；关联 `app/workers/handlers/agent_run.py:113`、`config.yaml`。

默认 data_dir 为 data，执行目录和脚本路径都保持相对路径。_run_py 把 data/projects/.../sandbox/hello.py 传给 Python，同时将 cwd 设为 data/projects/.../sandbox，导致子进程再次拼接同一前缀。

最小复现：在相对 sandbox 中创建 hello.py，调用 run_script。退出码为 2，错误路径出现 sandbox/data/projects/.../sandbox/hello.py。使用绝对 tmp_path 的已有测试没有暴露该问题。Shell runner 同样受影响。

建议：配置加载时规范化 data_dir 到稳定的绝对路径；工具解析返回绝对路径，或向 runner 传相对于 cwd 的正确路径。新增使用默认 config.yaml 的集成测试。

### F02 — P1：租约到期前重启，旧任务持续停在 running

位置：`app/workers/worker.py:61–69`；关联 `app/services/queue.py:recover_stale`。

run_forever 只在启动时调用 recover。Worker 被杀后如果在默认 60 秒租约到期前重启，旧任务当时不会被恢复；后续循环仅领取 queued，即使租约随后过期也没有扫描。

最小复现：领取短租约任务 → 在过期前调用新 Worker 的 recover → 等待到期 → run_once，任务仍为 running。已有真实进程中断测试先等待过期再 recover，遗漏了用户立即重启的路径。

建议：周期扫描过期任务，并协调活跃任务的独立心跳；不应直接对仍有活跃 Worker 的任务无条件中断。提供明确重试入口，记录新 attempt 与原结果关联。

### F03 — P1：首页 #/ 被当成空项目 ID

位置：`frontend/src/App.tsx:16–17,42–43,61,69–84`。

返回列表链接和标题写入 #/，解析 slice(2) 得到空字符串；渲染条件只认 null 为首页。hashchange 后会重新把 route 设为空字符串，显示项目面板并请求空项目 ID 的 API。

解析复现：空 hash → null → 首页；#/ → 空字符串 → 项目页。返回链接中的 setRoute(null) 不能抵消随后 hashchange 的赋值。

建议：统一 parseRoute，让 #/ 与空 hash 都返回首页；验证首页、进入项目、返回、浏览器前进后退及刷新。

### F04 — P1：已有需求绑定版本时无法删除项目

位置：`app/services/projects.py:225–227`；关联 `SkillVersion.brief_revision_id` 外键。

删除逻辑先删除 BriefRevision，但 SkillVersion 仍引用这些记录，且该外键没有相应级联规则，SQLite 外键校验使请求返回 500。

复现：建项目 → 导入并确认需求 → 创建技能版本 → DELETE 项目，得到 HTTP 500。只有空项目的删除测试不足以覆盖真实使用。

建议：制定关联数据删除顺序或统一级联策略；处理仍在执行的任务，并同步清理或归档项目文件。删除前展示清单与备份选项。数据库事务失败时必须回滚。

### F05 — P2：字符串前缀校验允许同名前缀目录的符号链接越界

位置：`app/tools/registry.py:94–97`；同类问题 `app/services/skill_files.py:109–116`。

使用 str(target.resolve()).startswith(str(root.resolve())) 判断包含关系，会把 sandbox-other 认为属于 sandbox。sandbox/link 指向同级 sandbox-other 后，read_file 可读取外部 marker.md。

复现仅使用审阅临时目录和无敏感内容的 marker 文件。此问题需要符号链接前置条件，不等于普通 ../ 已被放行。

建议：用路径层级关系判断并明确拒绝或处理符号链接；校验树枚举和产物收集也需同一规则。路径检查不是任意脚本的操作系统沙箱，文档不得据此宣称脚本完全隔离。

### F06 — P2：Origin 校验使用前缀而非真实来源

位置：`app/api/main.py:39–40`。

http://localhost.example.invalid 满足 localhost 前缀，被当成本地 Origin。带合法测试会话令牌请求 /api/me 得到 200；文档所称“非本源 Origin 一律 403”不成立。

建议：解析 scheme、hostname、port 后按明确允许的来源比较。会话令牌校验仍然存在，此发现不是无令牌鉴权绕过。

### F07 — P1：模型响应被截断仍标记 completed

位置：`app/executors/api_executor.py:144–151`。

执行器仅检查是否没有工具调用，忽略模型响应的 finish_reason。独立代码审阅使用假提供商返回 content=partial、finish_reason=length，原执行器仍返回 completed。

影响：未完成的输出进入正式评分，exit_reason_is=completed 甚至直接通过。类似 content_filter 也需要明确处理，不能只依赖没有工具调用。

建议：区分正常结束、截断、拒绝与协议异常，保存退出证据；加入截断响应回归测试。此次验证没有调用真实服务。

### F08 — P1：普通工具错误导致评测中断并遗留 running

位置：`app/tools/registry.py:130–131`；`app/executors/api_executor.py:164–165`；`app/workers/handlers/agent_run.py:127–130,153–155`。

模型请求 write_file 写到已存在目录时产生 IsADirectoryError。执行器仅捕获 ToolTimeout，其他异常向 Worker 逃逸，终止整个评测；已提交的 AgentRun 没有错误收尾，持续保留 running。

独立审阅通过本地假提供商复现工具异常。另一条相关路径是模型提供商未配置：provider_from_env 在 running 记录提交之后调用，因此 job failed 与 AgentRun running 不一致。无效候选版本同样可能留下已创建的 EvalRun。

模型工具参数为 JSON 数组时也未验证为对象，调用 arguments.get 会产生 AttributeError。属于相同输入校验与异常收尾问题。

建议：工具参数做结构校验；预期操作错误结构化回填模型；未知错误保留证据并让运行记录收尾；每例失败单独记录，不让普通单例错误中断余下用例。数据库异常则必须正确 rollback 再写入失败结果。

### F09 — P2：二进制产物存在性被误判

位置：`app/executors/api_executor.py:186–195`；关联程序评分中的 file_exists。

收集函数只保留 UTF-8 内容，遇到二进制编码错误就丢弃该文件。评分器再用内容字典的键判断文件存在，导致实际存在的 PNG、PDF、xlsx 等产物可能不被识别。

独立审阅创建含 PNG 二进制字节的真实文件，file_exists 返回 false。此问题不要求上传二进制技能资源，脚本生成产物即可触发。

建议：文件清单与文本内容分开保存；存在性检查基于清单，内容断言明确限制文本类型。二进制预览与下载走文件接口。

### F10 — P2：单轮超出总 token 预算仍标记 completed

位置：`app/executors/api_executor.py:129–151`。

预算仅在调用前判断；消耗后如果没有工具调用，立即返回 completed。独立审阅复现预算 100、响应用量 115，结果仍为 completed。

max_tokens 参数约束输出，不直接约束输入加输出总用量。建议调用前考虑输入估算，调用后明确标记超预算与实际用量；费用上限只能尽力控制，不能承诺已发生的调用费用可撤回。

## 5. 文档与实现的一致性

1. README 的“第一阶段完成”可以是阶段定位，但不应等同于完整个人版完成。
2. config.yaml 注释称相对路径基于项目根，load_config 实际保留相对 Path，仍受进程 cwd 影响。启动器从其他目录执行时，父进程与 cwd=ROOT 的子进程可能使用不同数据目录。
3. 文档中的“沙箱隔离”需要限定：read/write 工具有路径校验；run_script 的 cwd、扩展名与超时无法阻止脚本访问宿主文件或继承环境密钥。
4. 原有 83 项测试是有效基础，但不包含完整前端交互和真实模型协议验收；不宜据测试数量直接宣称日常流程已通过。
5. 能力声明固定 tools/json_mode/context，不等于已验证所有兼容端点；未接入的能力应标明。

## 6. 建议修复顺序

先修默认脚本路径、首页路由、过早重启和删除外键，再补执行器退出语义与结果收尾。之后修路径边界和 Origin 规则，并增加对应回归测试。

完成稳定性修复后继续交付自动生成、评审反馈、完整报告、盲评迭代、描述优化及打包安装。阶段顺序可以调整，但完整功能范围保持不变。

## 7. 再验收所需证据

- 默认相对配置运行脚本成功，且从其他 cwd 启动仍使用同一数据库。
- 页面完整走首页 → 项目 → 返回 → 刷新 → 前进后退。
- Worker 在租约前后两种重启时机均能正确处理旧任务。
- 有需求、版本、运行和评测记录的项目删除行为明确且数据一致。
- 截断、拒绝、预算耗尽、工具异常、模型未配置不会被误标成功或留下永久 running。
- 同名目录前缀与符号链接越界被拒，非本地 Origin 精确拒绝。
- 在目标操作系统重新安装平台依赖后完成前端构建和真实浏览器验收。
- 配置真实模型后，以受控样例验证接口、工具循环、用量及对照公平性。
