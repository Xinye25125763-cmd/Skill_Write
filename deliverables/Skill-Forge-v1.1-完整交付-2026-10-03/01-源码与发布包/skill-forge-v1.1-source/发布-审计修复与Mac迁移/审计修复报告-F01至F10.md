## 第一批（F01 / F03 / F02 / F04）

### F01 — data_dir 相对路径随 cwd 漂移
- `app/core/config.py`：新增 `_anchored_data_dir()`——yaml 或 `SKILLFORGE_DATA_DIR`
  环境变量给出的**相对**路径一律锚定到 config 文件所在目录（即项目根）再
  resolve 为绝对路径，与进程 cwd 完全解耦。
- `app/tools/registry.py` `run_script`：脚本用 resolve 后的绝对路径传给 runner，
  避免子进程 cwd=sandbox 时相对路径被二次拼接。
- 回归：`tests/test_config_paths.py`（yaml 锚定、env 锚定、跨 cwd 一致性、
  沙箱脚本跨 cwd 执行、兄弟文件读取共 5 项）。

### F03 — 前端空哈希路由
- 新增纯函数模块 `frontend/src/route.ts`：`parseRoute(hash)`——`#/`、空 id →
  null（主页），其余 → id。`App.tsx` 初始化与 hashchange 两处统一走它。
- 回归：`frontend/tests/parse-route.test.ts`（8 例，node 原生跑）。

### F02 — Worker 宕机后任务永久 running
- `app/workers/worker.py`：`run_forever` 周期性执行 `recover()` 清扫
  （`SKILLFORGE_RECOVER_SECONDS`，默认=租约时长）；租约内任务不动，过期任务
  置为 interrupted + `lease_expired` 错误码；活任务靠心跳续租保护。
- 回归：`tests/test_worker_recover.py`（含真实双进程用例：worker1 领取后被杀 →
  worker2 在租约内不动、租约过期后正确清扫）。

### F04 — 项目删除完整性
- `app/services/projects.py` `delete()` 重写，单事务内按 FK 安全顺序：
  ① 在途任务先 `request_cancel` + 落 cancelled（project_deleted）；② 逐子表
  删除（eval_case_results → eval_runs → agent_runs → suites → skill_versions，
  版本引用先置空）；③ 删项目行；④ 提交后 `shutil.rmtree` 磁盘目录。
- 回归：`tests/test_project_delete.py`（全关系删除、在途任务语义、失败回滚 3 项）。

## 第二批（F07 / F08 / F10）

### F07 — finish_reason 退出语义
- `app/executors/base.py`：`ExitReason` 新增 `TRUNCATED`。
- `app/executors/api_executor.py`：无工具调用收尾分支三层判定：
  `length` → **truncated**（可调大预算重试）；`content_filter` 等 →
  **model_failed**；None/stop → completed。前端两面板补"输出截断"标签。

### F10 — 消耗后预算检查
- `consume()` 之后：超预算 + 本轮无工具调用 + `finish_reason != "stop"` →
  **budget_exceeded**（error_detail 注明用量与 finish_reason）。
  超预算但 stop 正常收尾仍算 completed（成果已产出，仅略超支）。

### F08 — 四处兜底
1. **参数结构校验**：`tc.arguments` 非 dict → 回填
   `{"error": "invalid_arguments", ...}`，循环继续；
2. **工具异常兜底**：工具执行抛任何异常 → 回填
   `{"error": "tool_failed", "tool": ..., "message": "类型: 信息"}`，循环继续；
3. **agent_run 收尾**：`provider_from_env()` 前移到 AgentRun 行创建之前
   （未配置 provider 不留半行）；`executor.run()` 包 try/except，意外异常时
   run 行以 model_failed 收尾、job 仍 succeeded（执行结果非基础设施故障）；
4. **eval_run 单例隔离 + 基础设施分层**：
   - `VersionNotFound` / `ProviderNotConfigured` → EvalRun 收尾 failed 后上抛，
     job failed（保留 not_found / provider_not_configured 错误码，既有契约不变）；
   - 其余意外异常 → 该用例 exec_failed + rollback + 继续余下用例，评测
     job 正常 succeeded。
- 回归：`tests/test_exit_semantics.py`（11 项：F07×4、F10×2、F08①②×2、
  F08③×2、F08④×1）。

## 第三批（F05 / F06 / F09 + 文档）

### F05 — 路径层级检查
- `app/tools/registry.py` + `app/services/skill_files.py`：两处
  `str(...).startswith(...)` → `Path.is_relative_to()`。
- 缺陷场景：沙箱根 `…/sandbox` 时兄弟目录 `…/sandbox-evil` 被字符串前缀
  误判为沙箱内；is_relative_to 做路径组件层级判断，正确拒绝。

### F06 — Origin 精确比较
- `app/api/main.py`：新增 `origin_allowed()`——urlsplit 解析后 scheme ∈
  {http, https} 且 hostname 精确 ∈ {127.0.0.1, localhost, ::1}（端口不限）。
- 缺陷场景：`http://127.0.0.1.evil.com`、`http://localhost.evil.com` 旧实现
  误放行 → 现 403；`ftp://`、`file://`、非法 URL、非回环主机全部拒绝。

### F09 — sandbox_files 清单/内容分离
- `api_executor._collect_sandbox_files` 返回
  `{"files": [{path, size, text}], "text_contents": {path: content}}`：
  files 为**全量清单（含二进制）**，text_contents 仅 UTF-8 文本。
- `app/services/scoring.py`：
  - `file_exists` 查全量清单——**二进制产物存在性断言现在能通过**；
  - `file_contains` 查文本图，二进制给明确 detail「存在但非文本」；
  - 兼容旧版扁平映射（存量 AgentRun 行仍可评分）。
- 同步：ExecutorResult 注释、models docstring、前端 types-runs.ts、
  runs-pane.tsx（清单渲染 + 「二进制 · N B」标记）。
- 设计约束记录：write_file 走文本扩展名白名单，二进制产物只能由
  run_script 产生（e2e 测试按此真实路径构造）。
