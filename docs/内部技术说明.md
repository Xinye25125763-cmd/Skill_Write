# skill-forge 内部技术说明

> 面向维护者/二次开发者。覆盖全部子系统的实现细节、不变量与扩展点。
> 用户视角的使用说明见《用户使用指南.md》；跨阶段拼接总览见《S8-拼接说明.md》。

---

## 1. 系统概览

skill-forge 是本地单机运行的技能生产与评测工作台，服务两类进程：

- **API 进程**（`uvicorn app.api.main:app`）：只做读、草稿写与任务入队；
- **Worker 进程**（`python -m app.workers.worker`）：唯一写执行结果的组件。

两进程无直接通信，全部经 SQLite（`data/app.db`，WAL 模式）中的 `jobs` 表交接，
事件经 `workflow_events` 表以 SSE 推给前端。前端为构建产物（`frontend/dist`），
由 FastAPI 静态托管，hash 路由。

核心不变量（改动任何代码前先对照）：

1. API 不写执行结果（细化方案 §4.5 写路径收敛）。
2. 基础设施失败（provider 未配、版本/套件不存在）→ job `failed`；
   执行结果（六种退出原因）→ job `succeeded` + `exit_reason`。
3. 终态（succeeded/failed/cancelled/interrupted）不可覆盖，先提交者为准。
4. 版本不可变：创建后文件树只读，任何读写都过哈希校验。
5. 应用仅从环境变量读取密钥，不主动持久化；用户的 shell 配置与工具脚本不在此保证范围内。

## 2. 配置与启动（S1）

`app/core/config.py`：`AppConfig`（pydantic，frozen）。加载顺序
`config.yaml`（`SKILLFORGE_CONFIG` 可改路径）→ 环境变量最后覆盖
（`SKILLFORGE_DATA_DIR` / `SKILLFORGE_PORT`）。默认端口 8710，仅绑定 127.0.0.1。

`app/core/db.py`：SQLite 引擎工厂（WAL + foreign_keys ON）；
`run_startup_checks()` 做数据目录自检。

`launcher.py` 一键链路：端口预检（bind 探测，占用即 `PortInUseError`）→
数据目录自检 → `alembic upgrade head` → 生成 32 字节 URL-safe 令牌 →
拉起 API 与 Worker 两子进程（令牌经 env `SKILLFORGE_TOKEN` 注入）→
轮询 `/api/health` 就绪 → `webbrowser.open(base/#token=...)`。
**令牌经 URL 片段下发**：片段不随请求发给服务器、不进日志；前端读取后存
localStorage 并清除地址栏。Ctrl+C 时 terminate 两子进程（10 秒后 kill 兜底）。

鉴权：除 `/api/health` 外全部路由要求 `x-session-token` 头等于
`SKILLFORGE_TOKEN`。SSE 用 EventSource 不能带自定义头，令牌经 query 参数
传递。API 层另有 Origin 边界校验（防浏览器跨站携带）。

## 4. 任务队列（S4，`app/services/queue.py`）

**入队**：`enqueue(session, type, payload, idempotency_key=None)`。
同 `(type, idempotency_key)` 已存在则直接返回既有任务（去重不重跑）。
入队即追加 `job_created` 事件。

**领取**：`claim(worker_id, lease_seconds)` 单条 SQL——
`UPDATE jobs SET status='running', worker_id, lease_expires_at, heartbeat_at,
attempt+1 WHERE id = (SELECT id FROM jobs WHERE status='queued'
ORDER BY created_at LIMIT 1) RETURNING id`。条件更新即领取，原子。
FIFO 按 `created_at`。

**心跳**：`touch(job_id, lease_seconds, worker_id)` 更新 heartbeat 与
lease_expires_at（仅 running 且归属匹配）。Worker 独立线程以独立 Session
每约 lease/3 续租，覆盖阻塞模型请求；处理器边界 touch 作为补充。

**终态提交**：`complete(job_id, result)` / `fail(job_id, error_dict)` /
`mark_cancelled(job_id)` 通过条件 SQL 只更新 queued/running；Worker 提交额外检查
worker_id，陈旧 ORM 缓存不能覆盖终态。error 是结构化 dict（code/message，可带 errors 列表）。

**取消**：`request_cancel` 只置 `cancel_requested=1` 协作标记；Worker/
处理器在子任务边界轮询 `is_cancel_requested`，响应后 `mark_cancelled`。
取消不杀进程。

**恢复**：`recover_stale()`——`UPDATE ... SET status='interrupted',
error_json={"code":"lease_expired",...} WHERE status='running' AND
lease_expires_at < now RETURNING id`。Worker 启动时先跑恢复，常驻循环定期再扫描（真实杀进程
恢复有测试）。中断任务由用户决定重试（重新入队是新任务）。

**事件**：`append_event()` 返回 `event_id`（单调递增整数）。
`events_after(after_id, limit=100)` 供断线补取。事件类型枚举：
`job_created / progress / job_succeeded / job_failed / job_cancelled`。

Worker（`app/workers/worker.py`）：`run_forever()` = recover → 循环
`run_once()`（claim → `_execute`），空闲 sleep `SKILLFORGE_POLL_SECONDS`
（默认 0.5s）。租约默认 60s（`SKILLFORGE_LEASE_SECONDS`）。单任务异常
不拖垮循环，结构化落 `failed`。**启动需 1–2 秒导入开销**（S5 后含
httpx 链），测试勿写死短 sleep。

**处理器注册表**：`app/workers/handlers/__init__.py` 的
`@register("type")` 装饰器。现有：`version_create`、`agent_run`、
`eval_run`、`sleep`（测试用）。`HandlerContext` 提供
`touch() / event(stage, message, progress) / is_cancelled()`。
Worker `_execute` 的异常分类表：`JobCancelled → cancelled`；
`VersionConflictError → conflict`；`ProviderNotConfigured →
provider_not_configured`；`VersionNotFound/SuiteNotFound → not_found`；
`FileValidationError → validation_failed(errors[, warnings])`；
其余 `Exception → code=异常类名`。

## 5. 技能文件与不可变版本（S3，`app/services/skill_files.py`）

**草稿区**：`data/projects/{pid}/skills/draft/`，PUT 即保存（自动保存语义）。
写入校验（`normalize_relpath` + 边界）：

- 路径：相对路径、分隔符 `/`、拒绝 `..`/绝对路径/盘符/反斜杠穿越；
- 扩展名白名单 `ALLOWED_EXTS`；单文件 ≤ 1MB（`MAX_FILE_BYTES`）；
  全树 ≤ 5MB（`MAX_TOTAL_BYTES`）、≤ 200 文件（`MAX_FILES`）；
- 文本文件统一 UTF-8，写入 `newline="\n"`（防 CRLF 破坏哈希）。

**版本创建**（`version_create` 处理器，异步）：四重校验——
① SKILL.md 存在且必填；② 文件树路径合法；③ 逐文件哈希计算与
manifest 一致；④ 全树规范化哈希 `content_hash`（路径排序后逐文件
sha256 拼接再哈希，`_tree_hash`）。同名 label 已存在 → 409 语义
（`conflict`）；**相同内容哈希 → `VersionConflictError`（同内容版本拒绝重建）**。
版本落库后写 `data/projects/{pid}/skills/versions/{vid}/`（只读事实）。

**读取版本文件**：`read_version_file` 每次读都重算 sha256 与 manifest
比对，不匹配抛 `FileValidationError`（防篡改）。

## 6. 模型适配层（S5，`app/llm/`）

`base.py`：`Capabilities(tools/streaming/json_mode/max_context_tokens)`
（frozen dataclass）；`ChatMessage`（system/user/assistant/tool 四角色，
assistant 带 `tool_calls`，tool 带 `tool_call_id`）；`ToolCall(id, name,
arguments: dict)`；`ModelResponse(content, tool_calls, usage, finish_reason)`；
`Usage(prompt/completion/total_tokens)`。`ModelProvider` Protocol——
`complete(messages, *, tools, max_tokens, temperature)`。适配层只做协议
翻译不做业务。

`openai_compat.py`：OpenAI 兼容 HTTP 适配器（httpx）。消息序列化规则：
assistant 的 tool_calls arguments dict → JSON 字符串；tool 消息带
`tool_call_id`。错误分类为 `ModelError(message, status_code=...)`。
`provider_from_env()` 工厂：读 `SKILLFORGE_LLM_BASE_URL` /
`SKILLFORGE_LLM_MODEL` / `SKILLFORGE_LLM_API_KEY`，缺任一抛
`ProviderNotConfigured`。v1.5 M5 新增 `judge_provider_from_env()`：
裁判类调用（盲评评审、触发验证判定）优先读
`SKILLFORGE_JUDGE_LLM_BASE_URL` / `_MODEL` / `_API_KEY`，
任一必填项缺省即整体回落主模型（不做半套配置拼接）。
**接第二个提供商 = 新增一个 adapter 文件实现
Protocol，工厂加分支。**

## 7. 工具层（S5，`app/tools/registry.py`）

工具 schema（`TOOL_SCHEMAS`，OpenAI function calling 格式）：
`read_file(path, offset?, limit?)` / `write_file(path, content)` /
`run_script(path, args?)` / `read_tool_output(output_id, offset?, limit?)`。
`read_file` 支持按行分页，
offset 1 起始 + limit 行数，大文件分段读而非一次灌入历史）。

**沙箱**：每次执行的独立目录
`data/projects/{pid}/runs/{run_id}/sandbox/`。路径解析
`resolve_sandbox_path()` 复用 S3 的 `normalize_relpath` 全部穿越检查 +
resolve 后 `Path.is_relative_to` 层级判定双保险（F05：不用字符串
前缀比较，兄弟目录 `sandbox-evil` 不会误判为沙箱内）。
注意：这是路径层约束，脚本以普通子进程运行，无进程/网络隔离。

**错误哲学**：工具错误一律返回 JSON 错误串（`{"error": "path_rejected"
|"file_not_found"|"content_too_large"|"script_type_not_allowed"|
"unknown_tool", ...}`）回填模型上下文，**不抛异常打断循环**——模型可
自行纠错。唯二例外：`ToolTimeout`（脚本超时）上抛触发退出；
run_script 白名单 `.py/.sh/.ps1`（py 用 `sys.executable`，sh 用
`which(bash)`，ps1 用 `pwsh -NoProfile -NonInteractive`），超时 60s，
stdout/stderr 各截 1MB；单次工具输出回模型截 4 千字符
（`MAX_TOOL_OUTPUT_CHARS`，v1.5 M3A 由 2 万降档——工具输出随轮次
全部重发进上下文，是 token 膨胀主因；截断提示带 offset/limit 分页
指引）。write_file 内容 ≤ 1MB，写入 `newline="\n"`。

## 8. 执行器（S5，`app/executors/api_executor.py`）

`ApiExecutor.run(is_cancelled)` 自实现工具循环：

1. 轮次边界查取消 → `CANCELLED`；
2. 轮次预算（默认 40 轮）→ `BUDGET_EXCEEDED`；
3. token 预算**调用前**检查（防明知超限仍发请求）→ `BUDGET_EXCEEDED`；
4. `provider.complete` 抛 `ModelError` → `MODEL_FAILED`；
5. 模型返回后再次检查取消；带工具且预算耗尽时停止，不执行该轮工具。
   无 tool_calls 按 finish_reason 分类（正常 stop → `COMPLETED`，
   `_collect_sandbox_files()` 收集沙箱终态文件供评分）；
6. 有 tool_calls：assistant 消息（带 tool_calls）入历史 → 逐个执行工具
   → tool 消息回填 → 下一轮。工具超时 → `TOOL_TIMEOUT`。

`Budget`：token 与轮次双上限（默认 200_000 / 40，payload 可覆盖）；
`consume()` 累计 usage；`remaining_tokens()` 决定单次调用
`max_tokens=min(4096, remaining)`。每步经 `on_step` 回调（agent_run
用它续租 + 发 step 事件）。`ExecutorResult`：exit_reason、final_message、
steps（StepRecord：kind=model|tool、name、arguments、content、output、
usage、duration_ms）、total_usage、error_detail、sandbox_files、budget（limit_tokens/used_tokens/over_limit/overrun_tokens）、
history_window（v1.5 M3B：keep_rounds/compressed_messages/saved_chars）。

**v1.5 M3B 历史窗口化**：工具输出随轮次全部重发进上下文是 token 膨胀
主因（二次方增长）。每轮模型调用前，把窗口外（>`history_tool_keep_rounds`
轮之前，默认 3）且超过 600 字符的旧 tool 消息 content 原地降档为
头尾各 200 字符的摘要（带完整原始长度和 `read_tool_output` 的 `output_id`、
`offset/limit` 分段恢复指引；tool_call_id 配对不变，幂等不叠加）。完整工具
返回即时写入 `agent_run_tool_outputs`，StepRecord 同时保留 `output_id`、长度和全文；
模型每次最多取回 4000 字符，片段作为工具响应重新进入模型上下文。新进程可通过
`GET /api/runs/{run_id}/tool-outputs/{output_id}?offset={n}&limit={n}` 继续分页，
输出 ID 必须属于 URL 指定的运行。`run_script` 的 stdout/stderr JSON 原文也进入该存储，
因此长脚本结果的中段不依赖沙箱文件重跑即可恢复。`keep_rounds=0` 关闭窗口化，
行为与 v1.4 逐字节一致。agent_run 落库时把 history_window 统计并入
budget_json（无新迁移）。

六种退出原因枚举（`executors/base.py`）：`completed / truncated /
budget_exceeded / tool_timeout / model_failed / cancelled`——全部是执行
结果，不是基础设施失败。`finish_reason=length` → truncated（可调大
预算重试）；消耗后超预算且未正常收尾 → budget_exceeded；工具异常与
非对象参数以 JSON 错误回填模型，循环不中断（F08）。

## 9. agent_run 处理器（S5，`app/workers/handlers/agent_run.py`）

`execute_prompt(session, cfg, ctx, *, project_id, version_id, prompt,
max_tokens_total, max_rounds)` 是 S6 抽出的复用入口：
建沙箱 → `_prepare_sandbox`（有版本：`SkillFileService.read_version_file`
逐文件展开进沙箱，`newline="\n"`，返回
`SKILL_SYSTEM_TEMPLATE.format(skill_md=...)`；无版本：空沙箱 +
`BASELINE_SYSTEM_PROMPT`）→ 建 AgentRun 行（running）→
`ApiExecutor(...).run(is_cancelled=ctx.is_cancelled)` → 全部落库
（finished、exit_reason、steps_json、用量、sandbox_files_json）。
`handle()` 是其薄包装（job payload → 参数）。

**候选与基线的唯一差别**就是 `version_id` 有无：有则系统提示词装配
SKILL.md 且沙箱含快照；无则通用提示词 + 空沙箱。对照评测的因果链全部
源于此差异。

## 10. 评分（S6，`app/services/scoring.py`）

`score_assertions(assertions, *, sandbox_files, final_message, exit_reason)`
→ `[{type, description, passed, detail}]`。四种断言（F09 后
sandbox_files 为 `{files: [清单含二进制], text_contents: {仅文本}}`，
兼容旧版扁平映射）：

| 类型 | 字段 | 判定对象 |
|------|------|----------|
| `file_exists` | path | files 清单（含二进制） |
| `file_contains` | path, contains | text_contents（二进制给出明确 detail） |
| `text_contains` | contains | final_message |
| `exit_reason_is` | value | exit_reason |

三级错误语义（严格分层）：**断言不通过**（passed=false，正常结果）＜
**单条断言字段非法**（该条 failed + detail，不中断其余）＜ **断言列表整体
非数组/元素非对象**（抛 `ScoringError` → score_failed，评分步骤失败）。

## 11. eval_run 处理器（S6）

`GROUPS = ("candidate", "baseline")`；逐用例 × 逐组顺序执行。
每例流程：取消检查（取消 → skipped 行保留）→ `execute_prompt`
（candidate 传 version_id；baseline 传 None）→
`exit_reason != "completed"` → `exec_status="exec_failed"` 且**不评分**
（not_scored）；completed → 评分 → scored / score_failed（ScoringError，
带 score_error）。

`eval_run_view()`：逐例结果 + 按组汇总 `{cases, executed, exec_failed,
skipped, scored, score_failed, passed_total, assertions_total}`。
**汇总按组独立统计**（candidate 组的 score_failed 不计入 baseline 组）。
job 层面只有套件/版本不存在、provider 未配才会 failed；单例失败不
拖垮整个评测。

套件 API（`app/api/evals.py`）：创建同步 + 服务端校验（未知断言类型、
用例 ID 重复、必填缺失 → 422 带逐条 errors）；`cases_json` 只存用例数组。

## 12. 备份/恢复（S7，`app/services/backup.py` + `app/backup.py` CLI）

**备份** `create_backup(cfg, out_path)`：SQLite backup API 取一致快照
（WAL 下直接复制 db 文件不安全）→ zip 归档 manifest + app.db 快照 +
`data/` 其余文件（跳过 -wal/-shm 伴生文件；非相对安全名跳过）。
manifest：`{tool, manifest_version:1, created_at(UTC ISO), schema_version
(alembic), db_file, file_count}`。

**恢复** `restore_backup(zip, data_dir)`：`read_manifest`（非 zip / 缺
manifest / tool 不匹配 / manifest_version 过新 → `InvalidBackupError`）→
目标目录非空 → `TargetNotEmptyError`（绝不静默覆盖）→ zip 全成员名过
`_safe_arcname`（zip-slip 防护：拒绝绝对路径、盘符、`..`、结尾分隔符）→
解到临时目录 → `PRAGMA quick_check` 完整性校验 → 整体 move 进空目录。

CLI `python -m app.backup create|info|restore`，`BackupError` → stderr +
退出码 1。旧 schema 备份恢复后 `alembic upgrade head` 升级
（alembic_version 随快照保留）。**备份/恢复须停服**（SQLite 句柄）。

## 模型用量台账与重试审计

全流程 `budget_ledger` 使用 `stage@job_id:attempt` 作为有尝试语义的键。同一 job attempt 因持久化重试再次写入时覆盖该条，避免双扣；Worker 真正开始新 attempt 时建立新条目，历史 usage 保留并与新调用累计。Repair 另在 attempt id 中附上 repair round，eval-blind 和 trigger 采用各自 Job id/attempt。旧快照中不带 attempt 的键继续可读取。

生成阶段、执行器、盲评与触发分别记录 model call 数、已知 prompt/completion tokens、usage 缺失调用数和估算 tokens。某个调用失败但先前调用已返回 usage 时，先前实测数保留；整轮 usage 不完整时必须显式 `usage_missing_calls`，estimate 放在独立字段，不伪装为 measured usage。只有预留尚未结算的阶段维持预算预留值，estimated 与 unknown call 口径分开显示。

对照评测与触发的成本写入 EvalRun 元数据；台账写入失败被持久化为 `budget_ledger_error`，结果不能被解释为完整成本证据。生成阶段的台账写入异常会让当前 stage job 失败并保留 job error/已提交的预留，允许排查或恢复。最终 ZIP receipt 包含 generation attempt ledger 以及每个 contrast/judge/trigger EvalRun 的预算、实测、估算、未知调用和分项成本。

## 对照评测的预算优先级与用量口径

对照评测 API 将单次候选/基线执行预算与整套累计预算分开：`max_tokens_per_run` 限制每个 AgentRun，`max_tokens_total` 限制整套用例、候选/基线两组及 repeats 的累计；测试集 `budget.max_tokens_per_case` 可定义单次默认值，测试集 `budget.max_tokens_total` 定义整套默认值。优先级为 API 显式值 > 用例声明 > 套件声明 > 执行器默认。`suite_max_tokens_total` 是早期实现快照的兼容输入别名；两个累计字段同时出现时，以规范字段 `max_tokens_total` 为准。

Worker 在每次执行前以 `min(单次上限, 套件剩余额度)` 限定下一次 AgentRun。达到上限后后续执行保持 `skipped` 并写明原因。provider 正常返回 usage 时累计实测 token；请求失败且无 usage 时保留先前实测量，并按该次请求的 completion token 预算保守估算，估算量单独写入 `unknown_usage_estimated_tokens`，计入套件封顶而不伪装成精确实测。单个正在进行的 provider 响应可能因 prompt token 产生上限超额，视图同时记录实际与用于封顶决策的 `cap_accounted_tokens`。

Judge 在候选/基线完成后执行，独立报告用量，不消耗对照套件 cap；trigger 是单独的验证阶段，也独立列入导出收据。EvalRun 详情和最终 ZIP 收据分别展示单次上限、整套上限、实测/估算、触顶情况与候选/基线/judge/trigger 分项。初始生成流程收据若相关异步任务尚未结束，会明确标记预算明细待收据更新。
