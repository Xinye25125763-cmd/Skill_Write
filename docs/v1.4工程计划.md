# v1.4 工程计划：验证侧三补全（R2 方差分析 / R1 触发优化 / R3 盲评对照）

> 依据：docs/v1.4优化需求文档.md。实施顺序 **R2 → R1 → R3**（统计底座先行）。
> 基线：v1.3（commit 80b0f81），214 项后端测试全绿。

## 任务分解

### R2：评测方差分析（纯计算层，无新模型调用）

| 任务 | 内容 | 涉及 |
|---|---|---|
| R2-T1 | 迁移 0010：`eval_case_results` 增加 `attempt` 列（1 起始，默认 1，存量行即 attempt 1） | migrations/versions/0010_*.py |
| R2-T2 | 新模块 `app/generation/variance.py`：纯函数聚合层——单次尝试结论归一（exec/score 状态 → passed/failed/not_run）、多数决（平票算 failed，保守）、flaky 判定（尝试>1 且结论不一致）、non-discriminating 判定（两组同用例结论相同且都过）、组级 pass_rate 均值±标准差与 delta | 新文件 |
| R2-T3 | `eval_run` 处理器：用例支持 `repeats`（默认 1=现行为），逐 attempt 执行并落 attempt 序号；取消时该用例剩余 attempt 记 skipped | app/workers/handlers/eval_run.py |
| R2-T4 | `evaluate_candidate` 折算升级：按 (group, case_id) 聚合 attempt → 多数决结论 + flaky 标注入证据；eval:summary 证据扩展组级统计（均值±stddev、flaky 计数、non-discriminating 计数） | app/generation/evaluation.py |
| R2-T5 | `eval_run_view` 汇总升级：attempt 字段暴露 + 组级统计 + 预估/实际调用次数可见 | app/workers/handlers/eval_run.py |
| R2-T6 | 专项测试 tests/generation/test_variance.py：多数决边界（1/3、2/3、平票）、stddev、flaky/非区分标注、repeats=1 回归零破坏；全量回归 | tests/ |

**验收**：需求文档 §3.4 五条全满足；现有测试不改断言全过。

### R1：触发验证与优化（第六维 trigger）

| 任务 | 内容 | 涉及 |
|---|---|---|
| R1-T1 | 触发用例生成器：交付后排 `trigger_run` 任务（幂等键含 version_id），生成 20 条 should/should-not 用例（正例含口语化/错别字，负例取相邻领域）；干扰项 = 本项目其他已交付技能 description + 固定占位集 | app/generation/trigger.py（新） |
| R1-T2 | 触发判定执行：每条用例一次模型调用——呈现候选技能列表（目标+干扰项，随机排序），判定目标是否被选中；逐例结果入库（复用 EvalCaseResult，group=target，case_id=trigger:...） | app/workers/handlers/trigger_run.py（新） |
| R1-T3 | 评分与有界迭代：召回率/误触率/总分；低于阈值（0.85）→ 失败用例作证据驱动模型改写 description（≤3 轮，no_progress/rounds/length 三停止信号，1024 字符边界），改写产物 → 新版本冻结（不可变纪律：只有 frontmatter 变也是新版本） | app/generation/trigger.py |
| R1-T4 | 导出折算：`trigger:` 前缀检查折算进导出收据（`_DIMENSION_PREFIXES` 新增 trigger 维度；`_is_export_time_check` 加 trigger:）；不阻塞导出，如实标注 | app/generation/delivery.py、app/api/generation.py |
| R1-T5 | 预算记账：stage_id=`trigger`，预留+实际双写；用例集以 trigger_cases.json 形态随评测套件冻结（用户可改后重跑） | budget、suite |
| R1-T6 | 专项测试 tests/generation/test_trigger.py：正/负例判定、评分、三停止信号、1024 边界、导出折算 | tests/ |

### R3：盲评对照（eval:blind）

| 任务 | 内容 | 涉及 |
|---|---|---|
| R3-T1 | 盲化层：同用例 candidate/baseline 最终输出匿名 A/B（随机分配，映射入库可复验，不进提示） | app/generation/blind.py（新） |
| R3-T2 | 盲评执行：评审提示（用例原题+两份匿名输出+评维度）→ 结构化裁决（偏好 A/B/平手+归因文字）；归因必须引用输出实际内容（抽查验证）；失败隔离（不合 JSON → 该例评分失败） | app/workers/handlers/eval_run.py 扩展 |
| R3-T3 | 汇总与折算：偏好分布 → `eval:blind` 检查（多数平手 → not_run，证据不足不粉饰） | evaluation.py、delivery.py |
| R3-T4 | 专项测试 tests/generation/test_blind.py：随机性可复验、归因抽查、平手语义、失败隔离 | tests/ |

## 全局纪律（对齐需求文档 §6）

- 未运行/证据不足 → not_run，不阻塞导出，不回写冻结版本行；
- 214 项回归零破坏（R2 关键：repeats 默认 1 时行为逐字节一致）；
- 新增模型调用全进预算台账；
- 磁盘/数据库是唯一真相，进程重启可恢复；
- 导出收据与数据库对账一致。
