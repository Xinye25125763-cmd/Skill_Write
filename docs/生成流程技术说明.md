# 生成流程技术说明

本文档面向开发者，说明需求驱动生成流程的技术架构与关键设计决策。

## 架构总览

```
request_text
    │
    ▼
┌─────────┐    ┌─────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│ extract  │───▶│  plan   │───▶│ generate │───▶│ validate │───▶│  freeze  │
│ (T04)    │    │ (T05)   │    │ (T07)    │    │ (T09)    │    │ (T10)    │
└─────────┘    └─────────┘    └──────────┘    └──────────┘    └──────────┘
    │                                                  │              │
    │ awaiting_input                                   │              │

                                                        │
```

## 核心模块

### 需求提取（`app/generation/requirements.py`，T04）

- 模型结构化输出 → `RequirementContract`（Pydantic v2 frozen model）
- `confirmation: pending` 的必要需求 → `unanswered_gaps()` → 流程暂停
- 回答后确定性修订（`apply_answers`），不消耗模型调用
- 附件来源的需求强制 pending（不可直接 confirmed）

### 工程规划（`app/generation/planning.py`，T05）

- 合同 + 工程规则集 → `SkillPlan`（功能→文件→验收映射）
- 规则集由 `app/generation/policy.py` 加载（YAML profile，冲突解决）

### 代码生成（`app/generation/generator.py`，T07）

- 逐文件调用模型，生成写入暂存区
- 暂存：`stage_artifacts()` → `publish_candidate()` → 候选目录

### 静态验证（`app/generation/validation.py`，T09）

- 磁盘字节为唯一真相，独立于模型输出
- 检查：文件存在性、路径规范、扩展名、大小、编码、必填字段

### 版本冻结（`app/generation/versioning.py`，T10）

- 候选 → `SkillVersion` 行（不可变，content_hash 防篡改）
- 迁移 0009：增加 contract_json / report_json / profile_hash

### 预算控制（`app/generation/budget.py`，T11）

- token + 轮次双预算，阶段前预留、阶段后按实际记账
- 超限 → `budget_exceeded` 终态，可恢复执行

### 需求覆盖（`app/generation/coverage.py`，T12）

- 合同→方案→清单→报告：证明每个需求有对应验收
- 执行/人工类验收未运行 → `NOT_RUN`，收据如实携带

### 工具预检 / 修复 / 对照（T13–T15）

- `runtime.py`：运行条件与脚本依赖预检
- `repair.py`：证据驱动的有界自动修复（最多 N 轮，每轮须有证据改善）
- 对照评测：候选 vs 基线公平对比

### 打包导出（`app/generation/delivery.py`，T16）

- ZIP 布局：技能文件顶层 + `delivery/` 子目录（manifest / receipt / contract / report / profile）
- 敏感文件排除（`.env`、密钥等）+ 内容扫描（secret markers）
- `_tree_hash`：canonical path:hash → SHA-256，Windows 下显式 posix 路径排序
- 导出时交叉验证 `SkillVersion.content_hash`，篡改 → 409

### 网页交互（`frontend/src/generation-pane.tsx`，T17）

- React 组件：输入→轮询→问题→回答→收据→导出
- localStorage 持久化 flow_id（刷新恢复）
- revision-gating 轮询（避免无限 re-render）
- CAS 提交（revision + idempotency_key）

### 宿主验证（`app/platforms/`，T18）

- `HostAdapter` ABC → `CodexAdapter`
- `NATIVE_SOURCE = "codex-cli"` 防止 API 注入
- CLI probe（`subprocess.run codex --version`）+ records.json 验证

### 桥接客户端（`app/generation/skill_bridge.py`，T19）

- `forge_client.submit()`：显式调用入口
- `_http_post` patchable 网络层（测试可替换）
- 令牌仅走请求头，绝不出现在输出/日志/报告

## 关键设计决策

1. **Windows Path 排序**：`sorted(Path)` 在 Windows 上用 normcase 不区分大小写，破坏跨平台 hash 一致性。修复：显式 `sort(key=lambda t: t[0])` 按 posix 相对路径字符串。

2. **交付状态语义**：`DeliveryStatus.CANDIDATE` 当任何维度 NOT_RUN/FAILED 存在；全部 PASSED 才标记 DELIVERED。不假装成功。

3. **假模型 vs 真模型**：测试用 `ScriptedProvider`（剧本回放，同步 `complete()`），生产用 `provider_from_env()`（OpenAI 兼容 HTTP）。`provider_factory` 可 monkeypatch 替换。

4. **六阶段围栏**：终态围栏（delivered/cancelled/failed → 跳过）、CAS 围栏（revision 递增防过期覆盖）、取消围栏（发布前最后检查 `ctx.is_cancelled()`）。

## API 端点

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/projects/{pid}/generation-flows` | 提交生成流程（202） |
| GET | `/api/generation-flows/{flow_id}` | 查询流程状态 |
| POST | `/api/generation-flows/{flow_id}/cancel` | 取消流程 |
| POST | `/api/generation-flows/{flow_id}/answers` | 回答必要缺口 |
| POST | `/api/generation-flows/{flow_id}/resume` | 恢复暂停流程 |
| POST | `/api/projects/{pid}/skill-versions/{vid}/export` | 导出 ZIP |
| GET | `/api/projects/{pid}/skill-versions/{vid}/export/download` | 下载 ZIP |
