# skill-forge 用户使用指南

> 这是一台跑在你自己电脑上的"技能工厂"：你在这里**制作**技能（一份说明文档 + 配套文件），
> 让 AI 装配它执行任务，再和"没装配技能的 AI"对比成绩，用数据判断技能到底有没有用。
> 项目、版本、运行记录保存在本地；点击运行或评测会向所配置的模型端点发送提示词、技能正文以及进入模型上下文的工具输出。远程端点会收到这些内容；本地模型端点则按其自身配置处理。

---

## 一、你需要先准备什么

1. 一台 Windows 或 macOS 电脑，装有 [uv](https://docs.astral.sh/uv/)（Python 工具）。首次构建前端还需要 [Node.js](https://nodejs.org/) 和 npm；仅运行已构建好的发行目录时不需要 Node.js。
2. 一个"OpenAI 接口兼容"的大模型接入点（大多数模型服务商都提供这种格式），
   需要拿到三样东西：**接口地址**、**模型名**、**API 密钥**。

不需要模型也能用前面一半功能（建项目、写技能、存版本）；只有"试跑"和"评测"
这两步需要模型。

## 二、安装与首次启动

```bash
cd <skill-forge 项目目录>
uv sync --locked
cd frontend
npm ci
npm run build
cd ..
uv run python launcher.py
```

前端单测使用 Vitest 5；开发或运行前端测试建议 Node.js 22.12 或更新版本。`uv sync --locked` 按 `uv.lock` 安装 Python 依赖，依赖索引为公开 PyPI。

启动后会自动打开浏览器。如果没打开，手动访问启动器窗口里显示的地址即可。
窗口里会打印一个带 `#token=...` 的地址——**请用那个地址**，直接输不带
token 的地址会提示令牌缺失。

启动器窗口保持开着（它是 API 和 Worker 两个后台进程的父进程）。
**用完了在启动器窗口按 Ctrl+C 退出**，两个后台进程会一起关闭。

## 三、把模型接进来（想用试跑/评测前必做）

启动前设置三个环境变量。PowerShell：

```powershell
$env:SKILLFORGE_LLM_BASE_URL = "https://你的服务商/v1"
$env:SKILLFORGE_LLM_MODEL    = "模型名"
$env:SKILLFORGE_LLM_API_KEY  = "你的密钥"
uv run python launcher.py
```

macOS 的 zsh/bash：

```bash
export SKILLFORGE_LLM_BASE_URL="https://你的服务商/v1"
export SKILLFORGE_LLM_MODEL="模型名"
export SKILLFORGE_LLM_API_KEY="你的密钥"
uv run python launcher.py
```

环境变量必须在启动器所在的同一个终端进程中设置，启动器再将其传给 API 和 Worker。只在另一个终端或 Codex 会话中设置变量，不会传递给已经运行的进程。应用不主动把密钥写入数据库或备份；写进 shell 配置文件或脚本会使其落盘。

想每次自动生效，可以把前三行写进一个 `start.ps1`，以后双击/执行它启动。
应用从环境变量读取密钥，不主动写入数据库或备份。把密钥写进 shell 配置、命令历史或脚本仍会落盘；脚本子进程也可能继承环境。

**可选：给"裁判"调用配个单独的模型（v1.5）**。盲评评审和触发验证
判定这类验证侧调用，可以读另一组环境变量（比如更便宜或更强的模型）：

```powershell
$env:SKILLFORGE_JUDGE_LLM_BASE_URL = "https://你的服务商/v1"
$env:SKILLFORGE_JUDGE_LLM_MODEL    = "评审模型名"
$env:SKILLFORGE_JUDGE_LLM_API_KEY  = "你的密钥"
```

三项里 URL 和 MODEL 必须同时配才生效；缺任何一项就整体回落到上面的主模型，
不会把两边的配置拼在一起用。不配的话行为和以前完全一样。

没配会怎样？"试跑"和"评测"会直接报"未配置模型提供商"——这是正常提示，
其他功能不受影响。

## 四、日常使用流程（六个步骤）

### 第 1 步：建项目

页面左上角"新建项目"，起个名字（比如"会议纪要整理技能"）。

### 第 2 步：写需求（可选，但推荐）

进入项目后，"需求"区域可以导入一份结构化需求（brief）——描述这个技能
干什么、什么时候用、输入输出是什么。它的价值在于：以后创建版本时，
系统会记录"这个版本对应哪一版需求"，形成可追溯的演进历史。

如果你暂时不想整理需求，直接跳到第 3 步也完全可以。

### 第 3 步：写技能

"技能草稿"区域直接编辑 `SKILL.md`——这就是技能本体，一篇教 AI 做事的
说明文档（frontmatter 写 name/description，正文写操作说明）。也可以添加
其他配套文件。**保存是自动的**，写完就是草稿了。

### 第 4 步：冻结版本

点"创建版本"，给个标签（如 v1）。系统会校验技能结构、算出内容指纹，
把当前文件树原样封存——**之后你怎么改草稿，这个版本都不变**，
永远可以回来到"当时的它"。

### 第 5 步：试跑（需要模型）

选一个版本，输入一段任务提示词，点"运行"。AI 会装配你的技能
（系统会把 SKILL.md 装进它的系统指令），并在一个沙箱目录里干活——
它可以读文件、写文件、跑脚本，但**文件读写被限制在这个目录里**。
需要说明：这是路径层面的约束（防误访，不是操作系统级隔离），
脚本仍以普通子进程运行，理论上可访问网络；只对你信任的技能内容使用。

跑完能看到：最终答复、每一步轨迹（调了什么工具、返回什么、花多久）、
沙箱里最终有哪些文件。如果显示"预算耗尽""模型失败"之类的退出原因，
说明任务没跑完——换个更明确的提示词或更小的任务再试。

### 第 6 步：对照评测——看看技能到底有没有用（需要模型）

这是整个工作台最有价值的一步。先建一个**测试集**：若干用例，每个用例
= 一段任务提示词 + 几条自动判分规则（比如"沙箱里要出现 out/result.md"、
"答复里要包含 42"）。

然后选"测试集 + 候选版本"发起评测。系统会把**每个用例跑两遍**：
一遍是装配了你的技能的 AI（候选），一遍是什么技能都没有的 AI（基线），
最后并排展示两组成绩。**候选明显好于基线，才说明技能真在起作用**；
如果两组差不多，说明技能没提供真正的增益，该回炉重写了。

看结果时注意两个不同颜色的列：**执行状态**（任务跑没跑完——执行失败的
用例不参与评分）和**评分状态**（跑完了但判分规则本身写错了）。
"断言未通过"不是错误，就是没达标，正常看分数就行。

## 五、数据安全：备份与恢复

你的所有数据（项目、需求、版本、运行记录、评测结果）都保存在项目的 `data/` 目录；可通过 `SKILLFORGE_DATA_DIR` 指定其他位置。macOS 示例路径可以是 `~/Documents/skill-forge-data`。

**定期备份**（先关掉启动器，再执行）：

```bash
cd <skill-forge 项目目录>
uv run python -m app.backup create --out 我的备份.zip
```

**恢复**（换电脑、误删后）——恢复到的目标目录必须是空的：

```bash
uv run python -m app.backup restore 我的备份.zip --data-dir data
```

**常见问题**

| 问题 | 说明 |
|------|------|
| 打开页面提示"会话令牌缺失" | 没用启动器带 token 的地址打开；重启 launcher，用它打印的地址 |
| 启动报"端口被占用" | 上次没退干净；关掉旧窗口，或按提示改 `config.yaml` 里的端口 |
| 试跑一直转圈不结束 | Worker 启动有几秒延迟属正常；真卡住可以刷新页面看任务状态 |
| 想取消一个跑了一半的任务 | 任务详情里有取消按钮；它会在当前步骤结束后停下 |
| 想换一个模型 | 改那三个环境变量重启即可；历史记录不受影响 |
| "版本创建失败：相同内容版本已存在" | 一模一样的内容不需要再存一个版本，这是防重复保护 |
| 备份时报文件被占用 | 先 Ctrl+C 关掉启动器再备份 |

## 预算、用量与历史输出（v1.5）

- 运行详情和评测结果分别展示实测 token、用量未知的调用次数和保守估算。评委模型与触发验证成本单独列出；缺少 usage 字段时不会显示成实测零消耗。
- 单次运行上限与整套评测累计上限相互独立。显式 API 预算优先，其次使用用例/套件声明，最后才用默认值；达到套件累计上限后，剩余用例显示为跳过。
- 生成面板可设置全流程 token 上限，空白时使用默认 200,000；上限覆盖需求提取、规划、生成和修复阶段。达到额度后不会发起后续模型请求，流程会显示预算耗尽。当前正在进行的请求可能因输入 token 造成可见超额，系统会如实记账并停止后续阶段。
- 为控制上下文增长，旧轮较长工具结果在后续模型请求中会摘要化。完整结果仍保留在运行轨迹与本地存储中；模型需要时可用 `read_tool_output` 按偏移分页恢复，因此这是上下文窗口优化，不会删除可审计结果。
- v1.4 的重复尝试方差、触发验证与有界 description 优化、候选/基线盲评都保留独立结果与证据；未运行或证据不足时会明确标为未运行。

## 历史版本迁移提示

运行详情显示 token 预算与实际用量。输出完成和预算合规分别显示；看到“输出已完成，预算已超额”表示模型正常完成，但本次消耗超过计划预算。预算是调用边界的控制，输入token使单次请求仍可能超额。预算耗尽后不执行该轮工具，已产出文件可查看。

删除有运行中任务的项目会提示先取消并等待任务结束。结束后再次删除即可；排队任务随项目取消。删除提交后若暂存文件清理失败，API会返回X-Cleanup-Pending:true，下次启动自动重试；.trash 中残留文件仍占空间，勿把“项目消失”当成安全擦除。

升级先停止旧 API/Worker 并备份。更新源码后运行 `uv sync --locked`；若前端源码有更新，运行 `cd frontend && npm ci && npm run build`。启动器会自动将数据库迁移到当前版本。恢复备份时必须恢复到空目录。早期运行记录中未采集的预算与模型 usage 无法事后反推；具体请参阅 [内部技术说明](内部技术说明.md) 和版本修改报告。
